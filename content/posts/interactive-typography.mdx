<h2 id="curiosity">구경하던 UI를 직접 만들어보고 싶었다</h2>

평소에 재밌는 UI/UX를 보면 잠깐 멈춰서 이것저것 건드려보는 편이다. 버튼이 손끝에 붙어오는 느낌이나, 스크롤을 조금 되돌렸을 때 이어지는 움직임 같은 것들. 기능을 이해하고 나서도 마우스를 몇 번 더 움직이게 되는 화면이 있다.

그러다 우연히 마우스 근처의 글자들이 밀리거나 휘어지는 화면을 봤다. 마우스를 움직일 때마다 문단이 반응하는 게 재밌어서 한참을 건드려보다가, 나도 직접 만들어보고 싶어졌다. 이번 글에서는 **마우스와 글자 사이의 거리를 움직임으로 바꾸는 작은 실험**을 해보고, 그 과정을 기록해보려 한다.

<h2 id="playground">먼저 글자를 건드려보기</h2>

아래 문단 위로 마우스를 천천히 움직여보자. 가까운 글자는 마우스 반대쪽으로 밀려나고, 멀어지면 제자리로 돌아온다. 반응 범위를 넓히면 주변 글자가 함께 움직인다. 이동 강도를 높이면 문단이 더 크게 흐트러진다.

<InteractiveTypography />

휴대폰에서는 ‘움직임 체험’을 누르면 가상의 포인터가 문단을 가로지른다. 같은 계산을 쓰되 입력만 버튼으로 바꿨다. 기기의 동작 줄이기 설정이 켜져 있다면 글자는 움직이지 않는다.

이번에 만든 것은 글자의 획을 실제로 휘게 만드는 효과는 아니다. 각 글자를 조금씩 옮기고 기울여서 문단 전체가 느슨하게 흔들리도록 했다. 글자마다 반응하는 정도가 다르기 때문에, 단순한 이동도 모이면 제법 유기적으로 보인다.

<h2 id="distance">마우스와 글자 사이의 거리</h2>

처음에는 물리 엔진 같은 것이 필요할까 싶지만, 이 정도 효과는 거리 계산에서 시작할 수 있다. 글자의 중심과 마우스 좌표를 구한 뒤, 둘 사이가 얼마나 가까운지 계산한다. 이번 예제의 기본 반경은 110px, 최대 목표 이동량은 24px로 잡았다. 실제 이동량은 거리에 따라 줄어든다.

```js
const dx = letterCenterX - pointerX;
const dy = letterCenterY - pointerY;
const distance = Math.hypot(dx, dy);
const influence = Math.max(0, 1 - distance / radius) ** 2;

const targetX = dx / Math.max(distance, 1) * influence * strength;
const targetY = dy / Math.max(distance, 1) * influence * strength;
```

`influence`는 반경 밖에서 0이 된다. 가까워질수록 1에 가까워지고, 제곱을 해서 가장자리의 반응을 약하게 만들었다. `dx`, `dy`는 마우스에서 글자로 향하는 방향이므로, 이 방향으로 이동시키면 글자가 마우스를 피한다. 거리가 0일 때 나눗셈이 깨지지 않도록 분모에는 최솟값을 둔다.

여기서 중요한 것은 **움직이기 전의 글자 위치를 기준으로 계산하는 것**이다. 이동한 글자를 다시 측정하면 애니메이션이 자기 자신의 위치 변화에 반응하게 된다. 그래서 고정된 바깥 `span`으로 중심 좌표를 측정하고, 안쪽 `span`에만 `transform`을 적용했다. 글자의 원래 자리가 남아 있으니 움직일 때마다 줄바꿈도 다시 일어나지 않는다.

<h2 id="return">돌아오는 움직임이 인상을 만든다</h2>

목표 좌표를 곧바로 적용하면 글자가 마우스를 너무 딱딱하게 따라간다. 약간 늦게 반응하고, 부드럽게 멈추는 시간이 필요했다. 현재 위치와 목표 위치의 차이를 속도에 더하고, 속도를 조금씩 줄이는 방식으로 처리했다.

```js
velocityX = (velocityX + (targetX - x) * 0.12) * 0.75;
velocityY = (velocityY + (targetY - y) * 0.12) * 0.75;
x += velocityX;
y += velocityY;
```

`0.12`는 목표로 당기는 정도, `0.75`는 속도를 유지하는 비율이다. 마우스가 떠나면 목표를 `(0, 0)`으로 바꾸므로 같은 계산으로 원래 자리까지 돌아온다. 엄밀한 물리 시뮬레이션보다는 손으로 조절하기 쉬운 스프링 모델에 가깝다.

화면 갱신은 브라우저의 [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)에 맞췄다. 이 콜백의 빈도는 디스플레이 주사율에 따라 달라질 수 있다. 그래서 위 계산은 누적된 시간을 기준으로 1/60초 단위로 진행한다. 프레임이 오래 지연됐을 때는 따라잡을 시간을 제한했다. 탭을 다시 열었을 때 한꺼번에 크게 튀는 것을 피하기 위해서다.

마우스가 떠나고 글자가 멈추면 다음 프레임을 예약하지 않는다. 움직이는 동안에는 글자 좌표를 React 상태로 매번 갱신하는 대신, effect 안에 보관하고 DOM의 `transform`만 바꾼다. 슬라이더나 켜기·끄기처럼 화면의 설정이 바뀔 때만 React 상태를 사용한다.

<h2 id="next">Next.js 글 안에 작은 실험실 넣기</h2>

Next.js에서 쓸 수 있다고 해서 이 효과가 Next.js만의 기능인 것은 아니다. 핵심은 브라우저 이벤트와 좌표 계산이다. 이 블로그에서는 MDX 본문에 React 컴포넌트를 넣는 방식으로 연결했다.

글 본문은 그대로 두고, 마우스 이벤트와 브라우저 API를 사용하는 실험 컴포넌트에만 `"use client"`를 선언했다. Next.js는 이런 상호작용을 Client Component로 분리할 수 있고, MDX에서는 컴포넌트를 import해 본문 사이에 배치할 수 있다. [Server와 Client Component](https://nextjs.org/docs/app/getting-started/server-and-client-components) · [MDX 가이드](https://nextjs.org/docs/app/guides/mdx)

```mdx
import InteractiveTypography from "../../components/experiments/InteractiveTypography";

마우스로 직접 움직여보면 설명이 조금 더 쉬워진다.

<InteractiveTypography />
```

화면 너비가 바뀌거나 폰트가 준비되면 글자의 기준 위치를 다시 측정한다. 스크롤할 때도 현재 움직임을 초기화하고 좌표를 갱신한다. 이 구현에서는 움직임을 스크롤 중에도 유지하는 것보다, 다음 마우스 입력이 정확한 위치에서 시작하는 쪽을 택했다. 페이지를 떠날 때는 등록한 이벤트와 프레임 예약, 크기 감시도 정리한다.

<h2 id="after">작은 호기심도 글이 될 수 있다</h2>

이번에는 새로운 AI 모델이나 도구 대신, 마우스를 몇 번 더 움직여보고 싶었던 화면에서 출발했다. 기억에 남은 느낌을 좌표와 속도로 옮겨보니 어떤 부분을 조절해야 하는지도 조금 더 구체적으로 보였다. 반경 하나, 복귀 속도 하나가 화면의 인상을 바꾼다.

모든 페이지에 이런 움직임이 필요하지는 않을 것이다. 그래도 한 번 직접 만들어보면 다음에 비슷한 화면을 만났을 때 보는 지점이 달라질 것 같다. “신기하다”에서 한 걸음 더 나아가, 왜 이만큼 움직이고 여기서 멈추는지 궁금해진다.

앞으로도 가끔은 이런 작은 UI 실험을 기록해보고 싶다. 눈에 들어온 장면을 직접 다뤄보고, 그 과정에서 알게 된 것을 글과 함께 남기는 것도 충분히 재밌는 주제다.
